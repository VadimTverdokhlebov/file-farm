Глава 4. Программная реализация высоконагруженной системы и экспериментальное исследование эффективности балансировки нагрузки модифицированного алгоритма AM-PPO

4.1. Экспериментальный стенд и метрики оценки качества балансировки нагрузки

Для экспериментальной проверки разработанного метода AM-PPO был развёрнут испытательный стенд, реализующий структурно-функциональную схему распределённой системы, представленную на рисунке 1 (раздел 2.2), и воспроизводящий работу распределённого файлового сервиса в гетерогенном вычислительном кластере. Стенд запускался в ОС Ubuntu 24.04 и был развёрнут в среде Docker [10] на ПЭВМ со следующими характеристиками: Intel® Core™ i5-11400H CPU @ 2,70 ГГц (6 ядер, 12 потоков), 8 ГБ ОЗУ, выделенных виртуальной машине WSL 2.

Стенд включает следующие компоненты:

  • четыре backend-узла S1–S4 – экземпляры gRPC-сервера файлового сервиса с различными ресурсными ограничениями (таблица );
  • прокси-сервер Envoy (Data Plane), распределяющий входящие запросы между узлами в соответствии с весами конечных точек, поступающими через службу обнаружения конечных точек (EDS);
  • контроллер балансировки (Control Plane), реализующий исследуемые алгоритмы и формирующий веса узлов;
  • система мониторинга Prometheus с агентом cAdvisor, собирающая загрузку процессора, памяти и дисковой подсистемы, а также интенсивность и время обработки запросов на каждом узле;
  • нагрузочный стенд (генератор нагрузки клиентского слоя), формирующий поток запросов, управляющий отключением узлов и регистрирующий показатели качества обслуживания.

Кластер намеренно сделан гетерогенным: наиболее производительный узел S4 располагает вчетверо большей квотой процессорного времени, чем узлы S1 и S3. При равномерном распределении запросов каждый узел получает 25% потока, и слабые узлы оказываются перегружены вдвое относительно своей доли мощности, тогда как узел S4 остаётся недогруженным. Тем самым создаются условия, в которых качество балансировки непосредственно влияет на производительность системы в целом, а ограничение Ui(t) < 1 из постановки задачи раздела 2.1 может быть выполнено только при распределении весов с учётом мощности узлов.

Нагрузку формирует заданное число параллельных потоков (виртуальных клиентов), каждый из которых циклически выполняет шесть типов запросов: загрузку, скачивание, удаление и сжатие файла, создание и получение пользователя. Перед началом нагрузки на сервис загружается восемь файлов, чтобы операции скачивания и удаления имели объекты для обработки. Уровень нагрузки выражается долей от предельной вычислительной мощности кластера и подбирался предварительно числом потоков и размером передаваемых файлов. Отказ узла эмулируется остановкой его контейнера через Docker API в заданную секунду теста и последующим запуском; на графиках интервалы недоступности узлов отмечены затенёнными полосами с подписью S-n.

Каждый эксперимент выполнялся серией: один и тот же сценарий нагрузки последовательно воспроизводился для каждого из шести алгоритмов. Перед запуском очередного прогона стенд дожидался готовности всех узлов, чтобы все алгоритмы начинали работу на кластере одинакового состава. Для обеспечения сопоставимости результатов параметры политики AM-PPO, полученные в ходе обучения (раздел 3.4), в ходе испытаний фиксировались (онлайн-обучение отключалось), а решение принималось по математическому ожиданию распределения действий без исследовательского шума.

Для объективной оценки качества балансировки использовались следующие метрики: пропускная способность (RPS), медианная задержка (p50), 95-й (p95) и хвостовой (p99) перцентили времени ответа, доля ошибок (Error Rate), а также среднее абсолютное отклонение утилизации процессоров (CPU MAD – Mean Absolute Deviation). Пропускная способность определяется как число успешно обработанных запросов в единицу времени:

RPS=NokT,

где Nok – число успешных запросов; T – длительность теста, с. На графиках используется та же величина, вычисленная в скользящем окне длительностью 5 с.

Задержка обслуживания характеризуется перцентилями времени ответа p50, p95 и p99, которые вычисляются по гистограмме времени ответа:

pq=bk*, k*=min {k: ∑l=1khl ≥q100 ∑lhl},

где hl – число запросов в l-м интервале гистограммы; bk – верхняя граница k-го интервала. Медиана p50 отражает типичное время ответа, перцентиль p95 – время, в которое укладываются практически все запросы, p99 – редкие наихудшие случаи и соответствует показателю Tsysp99 математической модели раздела 2.1.

Равномерность распределения нагрузки оценивается средним абсолютным отклонением утилизации процессоров работающих узлов, вычисляемым ежесекундно и усредняемым за тест:

MADcpu(t)= 1N(t) ∑i:is_alivei=1 |Ui(t)− U¯(t)|, MAD¯cpu=1T ∑t=1T MADcpu(t),

где N(t) – число работающих узлов в секунду t; Ui(t) – нормализованный показатель утилизации процессора i-го узла относительно его квоты, %; Ū(t) – среднее арифметическое значение утилизации процессора по работающим узлам. Остановленные узлы в расчёт не включаются, поэтому отказ узла сам по себе не увеличивает показатель.

Надёжность обслуживания характеризуется долей запросов, завершившихся ошибкой:

Err= NerrNok+Nerr ·100%,

где Nerr – число запросов, завершившихся ошибкой или превышением времени ожидания.

4.2. Алгоритмы сравнения и математическая модель адаптивного алгоритма EMA

В сравнении участвовали шесть алгоритмов: четыре классических, реализованных средствами прокси-сервера Envoy или контроллера, адаптивный алгоритм на основе экспоненциального скользящего среднего (EMA) и разработанный метод AM-PPO. Все алгоритмы, задающие веса, оперируют целочисленными весами узлов с фиксированной суммой W = 1000; при отказе узла его вес обнуляется, а Envoy исключает узел из выбора.

Round Robin (RR) назначает всем узлам равные веса wi = W / N и перебирает их по кругу, где N – число работающих узлов. Random Choice (RC) выбирает узел для каждого запроса равновероятно, с вероятностью 1 / N. Оба алгоритма не учитывают ни производительность узлов, ни их текущее состояние.

Weighted Round Robin (WRR) использует статические веса, пропорциональные квотам процессорного времени узлов:

wi=W· cpui ∑j=1Ncpuj,

где cpui – квота CPU узла i из вектора ресурсов Ci (раздел 2.1). Алгоритм опирается на априорное знание конфигурации кластера, но не реагирует на фактическую загрузку узлов.

Least Request (LR) реализует стратегию «выбора из двух»: для каждого запроса случайно выбираются два узла a и b, и запрос направляется на тот из них, у которого меньше активных запросов:

i*= arg min i∈{a,b} qi(t),

где qi(t) – число запросов, обрабатываемых узлом i в момент t.

Для объективной оценки эффективности нейросетевого подхода в рамках единого контура управления (Control Plane) была реализована собственная стратегия адаптивной балансировки на основе экспоненциального скользящего среднего (EMA). Данный алгоритм выступает в роли сильного эталонного метода (baseline), динамически обновляющего веса конечных точек через протокол Envoy EDS с частотой 10 Гц (интервал 0,1 с).

В качестве единственной метрики наблюдения алгоритм использует 99-й перцентиль задержки узла xi(t), агрегируемый из Prometheus по минутным окнам. Значение скользящего среднего emai(t) для i-го узла вычисляется рекурсивно:

emai(t)= { xi(t),t=0; α·xi(t)+ (1−α)·emai(t−1), t>0,

где α = 0,2 – коэффициент сглаживания, формирующий эффективную «память» алгоритма глубиной около пяти шагов (1 / α).

Логика распределения базируется на обратной пропорциональности: чем ниже сглаженный показатель p99, тем больший приоритет получает сервер. Итоговый нормализованный вес wi ≥ 1 вычисляется относительно общей суммы весов кластера W = 1000:

si=1emai(t), wi=max(1, round( si∑j=1Nsj ·W)).

Полученные веса передаются в Data Plane, где прокси-сервер применяет механизм Weighted Round Robin.

Разработанный метод AM-PPO, математический аппарат и архитектура которого изложены в главе 3, формирует вектор весов по вектору состояния St из семи признаков на каждый узел с периодом Δt = 2 с. Изменение веса узла складывается на 70% из предсказания сети-актора и на 30% из поправки CPU-контроллера и ограничено ±20 пунктами за шаг; вес недоступного узла блокируется маской. Дополнительно узел, вернувшийся после отказа, наращивает вес не более чем на 10 пунктов за решение, что защищает его от перегрузки сразу после запуска. В отличие от EMA, реагирующего на уже возникшую задержку, AM-PPO учитывает загрузку процессоров и долю квот узлов, то есть причину, а не следствие перегрузки.

4.3. Экспериментальное исследование алгоритмов балансировки нагрузки

Исследование включало четыре эксперимента, различающихся уровнем нагрузки и характером отказов узлов. Длительность каждого прогона составляла 10 минут. В первом эксперименте все узлы доступны; во втором на время с 3-й по 6-ю минуту отключается слабый узел S1; в третьем последовательно отключаются S1 (с 3-й по 7-ю минуту) и S3 (с 5-й по 8-ю минуту); в четвёртом с 3-й по 8-ю минуту отключается наиболее производительный узел S4. С учётом квот работающих узлов средняя по времени доступная мощность кластера составляла 100; 96,3; 91,3 и 75% соответственно.

4.3.1. Эксперимент 1: стабильная высокая нагрузка

В первом эксперименте оценивалась эффективность алгоритмов балансировки в условиях стабильной высокой нагрузки при доступности всех узлов кластера. Нагрузочным стендом эмулировалась стабильная нагрузка в 85–90% от предельной вычислительной мощности кластера при 28 параллельных потоках. Длительность эксперимента составляла 10 минут. Результаты эксперимента 1

Алгоритм AM-PPO обеспечил наибольшую пропускную способность – 367,97 запросов в секунду, что на 4,8% выше, чем у WRR, на 15,4% выше, чем у EMA, и на 18,4% выше, чем у LR. Статические алгоритмы RR и RC уступили ему почти вдвое: равномерное распределение запросов перегружает слабые узлы S1 и S3, которые становятся узким местом всей системы, тогда как наиболее мощный узел S4 простаивает. Это же подтверждает показатель CPU MAD, составивший у RR и RC 25,6% и 24,5% против 4,2% у AM-PPO.

По задержке p95 AM-PPO (325,66 мс) практически совпадает с WRR (329,74 мс) и на 30–35% опережает EMA и LR. Наименьшая задержка p99 достигнута алгоритмом LR (744,66 мс), который при выборе узла для каждого запроса учитывает длину очереди и тем самым отсекает наиболее длительные ожидания; однако эта особенность не компенсирует его отставания по пропускной способности и задержке p95. Медианная задержка у всех алгоритмов, кроме LR, лежит в узком диапазоне 13,7–15,7 мс. Доля ошибок у AM-PPO минимальна (0,26%).

4.3.2. Эксперимент 2: отказ слабого узла

Во втором эксперименте оценивалась устойчивость алгоритмов балансировки к временному отказу слабого узла при высокой исходной нагрузке. Нагрузочным стендом эмулировалась стабильная нагрузка в 85–90% от предельной вычислительной мощности кластера при 28 параллельных потоках, с длительностью – 10 минут. На 3-й минуте принудительно отключался S1, который восстанавливался на 6-й минуте. Результаты сравнения сведены в таблицу и представлены на рисунках .

Результаты эксперимента 2

Узел S1 обеспечивает лишь 12,5% мощности кластера, поэтому его отказ существенно не меняет соотношения сил. По пропускной способности WRR незначительно опередил AM-PPO (323,37 против 319,07 запросов в секунду, разница 1,3%). Это объясняется тем, что при отказе узла статические веса WRR для оставшихся узлов сразу остаются пропорциональными их мощности, тогда как AM-PPO изменяет веса ограниченными шагами, а вернувшийся узел наращивает вес постепенно, чтобы не допустить его перегрузки сразу после запуска. Вместе с тем AM-PPO обеспечил меньшие задержки p95 (405,87 против 465,65 мс, на 12,8%) и p99 (755,90 против 1230,46 мс, на 38,6%), а также наиболее равномерную загрузку узлов (CPU MAD 3,89% против 6,80%).

Наибольшую чувствительность к отказу показал RR: по сравнению с первым экспериментом его пропускная способность снизилась на 19,2%, а задержка p95 выросла на 31,4%. Доля ошибок наибольшая у RC (1,23%), наименьшая – у LR (0,26%); у AM-PPO и WRR она практически одинакова (0,48% и 0,46%).

4.3.3. Эксперимент 3: последовательные отказы при умеренной нагрузке

В третьем эксперименте оценивалась способность алгоритмов балансировки адаптироваться к последовательным изменениям состава доступных узлов при умеренной исходной нагрузке. Нагрузочным стендом эмулировалась стабильная нагрузка в 55–60% от предельной вычислительной мощности кластера при 6 параллельных потоках, длительность – 10 минут. На 3-й минуте принудительно отключался сервер S1, который восстанавливался на 7-й минуте. Сервер S3 отключался на 5-й минуте и восстанавливался на 8-й. 4.3.4. Эксперимент 4: отказ наиболее производительного узла

В четвёртом эксперименте оценивалась устойчивость алгоритмов балансировки к отказу наиболее производительного узла при нагрузке, близкой к предельной. Нагрузочным стендом эмулировалась стабильная нагрузка в 95–100% от предельной мощности кластера при 32 параллельных потоках, длительность – 10 минут. Результаты эксперимента 4

Отказ узла S4 на пять минут лишает кластер в среднем четверти мощности, а на время отказа – половины. В этих условиях различия между адаптивными алгоритмами сокращаются: пропускная способность AM-PPO, EMA, LR и WRR лежит в диапазоне 246–260 запросов в секунду, при этом AM-PPO сохраняет первенство (260,02). По задержке p99 лучшим оказался LR (961,86 мс), по равномерности загрузки – EMA (CPU MAD 4,54%).

Статические алгоритмы RR и RC демонстрируют наименьшую медианную задержку (13,19 и 16,78 мс) при задержке p95, в 2,3 раза превышающей результат AM-PPO. Такое сочетание свидетельствует о бимодальном распределении времени ответа: запросы, попавшие на недогруженный узел, обслуживаются быстро, а попавшие на перегруженный – длительно ожидают в очереди. Медиана в этом случае не отражает качество обслуживания, что учитывается при выборе весов критериев в разделе 4.4.

4.4. Мультикритериальная оценка эффективности алгоритмов

Результаты экспериментов показывают, что ни один алгоритм не является лучшим одновременно по всем показателям: AM-PPO лидирует по пропускной способности и задержке p95, LR в ряде сценариев – по задержке p99, статические алгоритмы – по медианной задержке. Для получения обобщённой оценки применены методы многокритериального принятия решений: аддитивная свёртка критериев (WSM), метод TOPSIS и метод взвешенных рангов.

Для каждого эксперимента k = 1, …, K формируется матрица решений:

X(k)= ‖xij(k)‖ m×n,

где xij – значение j-го критерия для i-го алгоритма; m = 6 – число алгоритмов; n = 6 – число критериев; K = 4 – число экспериментов. Множество критериев разбивается на максимизируемые J+ = {RPS} и минимизируемые J− = {p50, p95, p99, CPU MAD, Err}.

Поскольку критерии измеряются в разных единицах, перед свёрткой они приводятся к безразмерному виду линейной нормализацией внутри каждого эксперимента:

rij= { xij−xjmin xjmax−xjmin, j∈J+; xjmax−xij xjmax−xjmin, j∈J−,

где xjmin и xjmax – наименьшее и наибольшее значения j-го критерия среди алгоритмов. Нормированное значение rij ∈ [0; 1] равно единице для лучшего алгоритма по данному критерию и нулю – для худшего.

Интегральная оценка по методу аддитивной свёртки:

Si= ∑j=1n wjrij, ∑j=1n wj=1,

где wj – весовой коэффициент j-го критерия.

Весовые коэффициенты назначены исходя из того, насколько критерий отражает качество распределения нагрузки, воспринимаемое клиентами сервиса (таблица ).

Основной вес отдан пропускной способности и задержке p95: именно они определяют, сколько запросов обслуживает кластер и за какое время их получает подавляющее большинство клиентов. Медианной задержке назначен умеренный вес, так как, по результатам эксперимента 4, она может скрывать перегрузку части узлов. Задержка p99 определяется одним процентом наиболее медленных запросов и в пределах одного прогона подвержена значительным случайным колебаниям, поэтому её вес снижен. Показатель CPU MAD характеризует внутреннее состояние кластера и сказывается на клиентах опосредованно, через пропускную способность и задержки, уже учтённые другими критериями. Доля ошибок у всех алгоритмов не превышает 1,3%, а различия между ними сопоставимы со случайным разбросом, поэтому этот критерий также имеет малый вес.

Метод TOPSIS ранжирует альтернативы по близости к идеальному решению. Применяется векторная нормализация с учётом весов:

vij=wj xij ∑l=1m xlj2.

Идеальное A+ и антиидеальное A− решения составляются из лучших и худших значений каждого критерия:

vj+= { maxivij,j∈J+; minivij,j∈J−; vj−= { minivij,j∈J+; maxivij,j∈J−.

Расстояния до идеального и антиидеального решений и коэффициент относительной близости:

Di±= ∑j=1n (vij−vj±)2, Ci= Di−Di++Di−.

Коэффициент Ci ∈ [0; 1] равен единице, если алгоритм совпадает с идеальным решением.

В методе взвешенных рангов каждому алгоритму по каждому критерию присваивается ранг ρij ∈ {1, …, m} (1 – лучший), после чего вычисляется средневзвешенный ранг:

Ri= ∑j=1n wjρij.

Итоговая оценка алгоритма по совокупности экспериментов вычисляется как среднее арифметическое оценок по отдельным экспериментам:

S¯i=1K ∑k=1K Si(k).

Лучший алгоритм по каждому критерию

Наличие компромиссов формально описывается отношением доминирования по Парето. Алгоритм a доминирует алгоритм b, если он не хуже по всем критериям и строго лучше хотя бы по одному:

a≻b⇔ ∀j:xaj⪰xbj ∧ ∃j:xaj≻xbj,

где отношение «⪰» означает «не хуже» с учётом направления критерия. По полному набору из шести критериев почти все алгоритмы оказываются недоминируемыми, поскольку каждый лидирует хотя бы по одному показателю; это и обусловливает необходимость свёртки критериев. Если же ограничиться двумя основными критериями – пропускной способностью и задержкой p95, – то в экспериментах 1, 3 и 4 фронт Парето состоит из единственного алгоритма AM-PPO, а в эксперименте 2 его разделяют AM-PPO и WRR (рисунок ).

При всех наборах весов порядок алгоритмов сохраняется, меняются лишь абсолютные значения оценок. При учёте только пропускной способности и задержки p95 оценка AM-PPO достигает 0,997, то есть алгоритм является лучшим по обоим критериям практически во всех экспериментах. При равных весах, когда существенное влияние получают медианная задержка и доля ошибок, отрыв AM-PPO сокращается, но сохраняется (0,845 против 0,761 у WRR). Таким образом, вывод о преимуществе AM-PPO устойчив к выбору весовых коэффициентов.

4.5. Выводы по главе 4

С целью экспериментальной проверки разработанного алгоритма развёрнут испытательный стенд, включающий неоднородный кластер из четырёх gRPC-серверов с квотами процессорного времени от 0,5 до 2 ядер, прокси-сервер Envoy, контроллер балансировки, систему мониторинга и нагрузочный стенд с возможностью эмуляции отказов узлов. Разработана методика проведения сравнительных испытаний, при которой все алгоритмы последовательно испытываются на одинаковых сценариях нагрузки, а параметры политики AM-PPO фиксируются.

Проведены четыре эксперимента, охватывающие стабильную высокую нагрузку, отказ слабого узла, последовательные отказы при умеренной нагрузке и отказ наиболее производительного узла при нагрузке, близкой к предельной. В трёх экспериментах из четырёх AM-PPO обеспечил наибольшую пропускную способность, во всех четырёх – наименьшую задержку p95, в трёх из четырёх – наиболее равномерную загрузку процессоров узлов. Статические алгоритмы RR и RC в условиях неоднородного кластера уступают AM-PPO по пропускной способности в 1,4–2 раза и многократно – по равномерности загрузки.

Для обобщения результатов выполнена мультикритериальная оценка эффективности алгоритмов методами аддитивной свёртки, TOPSIS и взвешенных рангов с весовыми коэффициентами, отражающими значимость критериев для клиентов сервиса. Все методы дали одинаковое ранжирование: AM-PPO (средняя оценка 0,889), WRR (0,820), EMA (0,766), LR (0,680), RR (0,203), RC (0,175). Анализ чувствительности показал, что ранжирование сохраняется при изменении весов в широких пределах.

Выявлены следующие преимущества алгоритма AM-PPO:

  • наибольшая интегральная оценка эффективности во всех исследованных сценариях;
  • одновременное улучшение пропускной способности и задержки p95, благодаря которому алгоритм единолично образует фронт Парето по этим критериям в трёх сценариях из четырёх;
  • учёт как априорных сведений о квотах ресурсов узлов, так и их текущей загрузки, что обеспечивает равномерное распределение нагрузки в неоднородном кластере;
  • сохранение работоспособности при изменении состава кластера без перенастройки, поскольку архитектура политики не зависит от числа узлов.

Вместе с тем выявлены ограничения алгоритма:

  • ограничение шага изменения весов, предотвращающее резкие колебания нагрузки, замедляет реакцию на отказ и восстановление узла, вследствие чего при отказе слабого узла WRR незначительно превосходит AM-PPO по пропускной способности;
  • по задержке p99 алгоритм в ряде сценариев уступает LR, принимающему решение для каждого запроса;
  • медианная задержка AM-PPO несколько выше, чем у статических алгоритмов;
  • для работы алгоритма требуются предварительное обучение политики и инфраструктура сбора метрик, а период принятия решений ограничен интервалом опроса системы мониторинга.

По итогам экспериментальных исследований можно заключить, что разработанный алгоритм AM-PPO является эффективным средством балансировки нагрузки в неоднородных кластерах, обеспечивая в совокупности лучшие показатели пропускной способности и времени отклика по сравнению с классическими и адаптивными алгоритмами, в том числе в условиях отказов узлов.
